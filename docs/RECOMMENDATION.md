# 推荐引擎

## 模块与输入

`packages/recommendation/index.ts` 导出 `recommendActivities` 与 `recommendPosts`。二者读取 `RecommendationInput`，返回 `RecommendationResult`，不操作数据库、网络或 UI。`now` 必须由调用者显式传入，不能用系统时间改变快照的候选与画像。同一快照、身份、参数、时间和探索种子产生相同的排名与分项，`elapsedMs` 仅是实际计算耗时。

活动候选需要已发布、未取消、尚未开始、未结束、报名未截止、未满员，且当前用户尚未报名。帖子按自身发布时间过滤，历史活动的回顾帖仍可阅读。关注流应由 Service 按关注对象与发布时间查询，不调用推荐引擎冒充算法排序。

## 画像

活动与帖子各建画像，共享用户显式兴趣，不把帖子行为自动转为其关联活动的报名偏好。

- 显式兴趣限制在 0–1，负数与非法值不加入。
- 当前点赞、收藏、报名的强度分别为 0.2、0.4、0.6，按三十天半衰期衰减。只读取当前状态，历史点赞或取消事件不累计强证据。同对象同种状态去重。
- 浏览按用户、对象和 UTC 日期汇总有效前台停留，单对象单日最多三十秒。少于三秒不贡献，三十秒贡献 0.08，并进行时间衰减。仅读取逻辑 VIEW，不读取心跳数或重复叠加 ViewSession。
- 同对象总推断强度最多 0.8，平均分配到其独立标签，每个标签总推断强度再封顶 0.8。推断贡献附加到显式兴趣，不覆盖用户填写的兴趣。
- 评论不直接增加兴趣，防止将提问与质疑当作喜欢。历史 COMMENT 事件也不当强正反馈。

客户端前台可见性、单会话封顶与心跳幂等属于停留 Service 的职责，算法在可信有效时长之上再做每日贡献限制。撤销点赞、收藏和报名后，相关当前状态贡献消失，独立存在的真实浏览证据仍保留。

这些数值是可解释的初始规则，不是根据真实用户效果拟合的最优参数。

## 评分与证据

兴趣分是画像与候选独立标签的余弦相似度，零向量返回 0。社交证据只使用已接受好友和本人发起的单向关注，两类关系独立。

`social = 0.65 × 有证据好友数 / 好友总数 + 0.35 × 有证据关注人数 / 关注总数`

无对应关系时该项为 0。活动证据来自活动的当前状态参与者，帖子证据来自帖子作者、当前互动者和评论作者。发布活动本身不等于参加活动，关联帖的评论不直接冒充活动报名。好友与关注交叠的用户会在两个独立关系分项内出现，但总社交分仍不超过 1。解释中的 `friendIds` 与 `followIds` 是实际命中的用户，不是文案推测。

活动热度为有效报名数 / 容量，活动情境分为同校区 1、其他 0，不推算地理距离。帖子热度为去重后的当前互动 / 评论用户数除以 20，封顶 1，作者发布本身不增加热度。帖子情境分是十四天半衰期的发布时间新鲜度。

活动默认权重为兴趣 0.55、社交 0.25、热度 0.10、情境 0.10。帖子默认权重为兴趣 0.55、社交 0.20、热度 0.10、情境 0.15。传入权重必须有限、非负且总和大于零，引擎按总和归一化。

`parts` 保存原始 0–1 分项，`contributions` 保存乘权后的真实贡献，`relevanceScore` 为四项贡献之和，未启用探索时 `score` 等于该值，启用探索时 `score` 为下述综合排序分。无画像、好友、关注时标记 `fallback`，活动只使用全局报名热度，帖子使用全局热度与新鲜度。该兜底不使用校区，分数相同按 ID 升序稳定输出。

## Top-K 与复杂度

`heap.ts` 自行实现最小堆，不以完整排序替代筛选。比较器将得分更高视为更优，得分相同时 ID 更小更优，堆根始终是已保留结果中最差者。扫描候选后，只对 K 个保留项做最终排序。K 非有限或小于等于零返回空结果，K 向下取整，候选少于 K 时返回全部候选。

详细追踪仅由第二个可选参数 `TraceOptions` 启用，默认产品调用不生成事件，也不收集旧摘要字符串。`packages/recommendation/trace.ts` 定义 profile、filter、score、candidate、compare、insert、remove、swap、retain、replace、skip、output 和 truncated。堆事件来自真实 MinHeap 操作，携带当时的节点状态和索引，不是前端预先编排动画。

Studio API 记录最多 10000 个正常步骤与一个截断标记。推荐包还对调用方设置的上限做有限值处理和 10000 的硬上界，NaN/Infinity 回到默认限制。截断只影响过程记录，候选计算与最终结果继续完整执行，界面必须说明当前轨迹不完整。旧字符串摘要仅在显式追踪时保留最多 200 项。

设快照总行数为 N，候选数为 C，画像维数为 D，好友与关注总邻居数为 L。画像与关系 / 互动预处理约 O(N)，评分与社交证据整理约 O(C(D+L log(L+1)))，其中命中的好友 / 关注 ID 还需要排序，堆选择 O(C log K)，最终排序 O(K log K)。实现保留候选数组和按目标去重的证据集合，总额外空间约 O(N+C+D+K)，不是整个引擎只使用 O(K) 空间。仅 Top-K 堆的空间为 O(K)。数据库读取、JSON 反序列化和传输不计入引擎 `elapsedMs`，端到端性能需单独测量。

## 产品内容流与 Top-K 的区别

活动 Top-K 和 Studio 用容量 K 的堆筛选当前候选。产品推荐内容流需要固定一次浏览会话中的完整排序，目前服务端传入 `k = snapshot.posts.length`，再保留排序 ID 与解释供游标分页。因此这条路径的堆和最终排序量级是 O(C log C)，不能把它宣传成每一页只用 O(C log K) 选十几项。关注流按时间和稳定 ID 排序，不伪称个性化推荐。

客户端拿到分页 DTO，完整算法快照只留在服务端。当前服务端构造输入仍加载全站关系和行为，尚未实现大规模召回、增量画像或分布式排序会话。

## Studio 图形与参数

Studio 当前直接只读主站完整数据，不再使用 240 帖离线子集。Studio 的五个阶段为用户与关系、候选筛选、匹配评分、Top-K 堆和推荐结果。图形分别是兴趣条与一跳关系图、候选状态点阵、分数分布与真实贡献条、实际树形堆及文本步骤、最终排名。当前局部关系图最多显示 12 人，并明确标示范围。

可调参数包括用户、活动/帖子目标、K（API 0–50）、冻结时刻、四项非负权重。权重计算时归一化。提供播放、暂停、前后单步、速度、进度拖动与重置，减少动态效果偏好下禁用自动播放。参数变化同步停止回放并取消旧请求，即使请求层忽略取消也用序列和签名拒绝旧结果。

Studio 的 `/feed` 另行演示内容自动滚动，只读自身文件快照，不发送产品阅读或互动。到末尾停止，用户操作接管，不能用滚动速度产生画像证据。详见 [Studio 说明](../apps/studio/README.md)。

## 验证与边界

当前实现以现有 small 快照核对 20 用户和 K=0/1/3/20 共 80 组，开启详细追踪不改变结果，默认追踪为空。1200 个包含同分的确定性候选在 K=0/1/6/50/1500 下与同比较规则完整排序一致。核对逐项贡献求和、轨迹截断及非法上限处理。

Studio 类型、Lint、构建及独立 API/SSR 已执行核验，控制逻辑另以真实页面脚本和模拟时钟/视口核对取消与滚动状态。这些证据不代替最终浏览器图形、动画和窄屏验收，实际整体验收由对应记录确认。

本引擎是可解释规则和每用户 Top-K，不是全局最大匹配，权重不是由真实点击率训练，共同好友数不是当前评分项。不得从内部结构数据推断真实推荐满意度。

## 刷新与受控探索

产品推荐与 Studio 共同使用带种子的候选探索。默认综合排序分为 `0.88 × 四项加权匹配分 + 0.12 × 探索分`，探索分是以本轮种子、用户、目标类型与内容 ID 计算的 0–1 确定性散列值。活动资格与发布时间筛选保持不变，兴趣、社交、热度与情境的规则不变，探索强度是当前人工设定的产品参数，并非通过真实用户效果拟合。

Top-K 使用综合排序分真实比较，轨迹和最终结果使用同一分数。Studio 分项仍展示原四项匹配贡献，另行展示匹配分与探索分的混合公式，分布条将四项贡献乘以 88% 并补上探索贡献，不伪造解释。

主站推荐流每次建立新的浏览会话生成新种子，固定整轮排序后再分页，追加下一页不重抽、不重复插入，关注流仍按发布时间排序。刷新改变已有内容的排序与部分前排成员，不生成新帖子，也不保证所有高匹配内容都不重复。活动浏览的完整目录仍按原来的活动时间组织，活动推荐接口与右侧推荐使用探索。

Studio 页面初次加载或点击换一批/重新计算会建立新种子，修改用户、对象、K、时间或权重时保留该轮种子，以便比较参数影响。种子不写入业务数据或左侧设置路由，整页刷新允许开始新一轮，路由仍恢复用户设置。引擎本身不读取时钟、不调用随机数，明确传入相同种子可复现排名，未传探索配置时继续支持原确定性评分。

Studio 的数据源由独立快照改为实时只读主站库，旧 240 帖子集与历史验收数字不再代表当前输入。读取与推荐分别在短只读事务和内存中执行，不产生阅读、点赞、收藏或报名状态。默认使用本次读取时刻，只有显式固定时间模式才保留历史基准。主站行为变更后，数据版本检查触发新计算，并保持本轮探索种子不变，以便观察行为本身的影响。
