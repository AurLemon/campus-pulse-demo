# 内容生成与审样规范

## 数据边界

内容维护工具可以生产明确记录来源的虚构人物、活动、帖子和讨论。来源、原始输出、模型与费用记录留在内部，公共产品正文和 DTO 不显示生成说明或任务背景。

真实产品仅用于观察信息层次与表达规律，不把私人推荐流、账号、原帖、评论、图片或身份信息发送给 DS，也不复制成产品内容。素材有独立来源和使用条件，不等于真实校园实拍。

## 人物先于正文

人物至少有主次兴趣、活动动机、表达习惯、活跃度和关系背景。摄影、编程、运动、动漫绘画、音乐、志愿、阅读语言等圈层可以交叉，同圈子不代表同一种口吻。

昵称包含普通小名、食物动物、拼音/英文/数字和少量表情，不使用兴趣词加流水号。简介可以空白，不泄漏 voice、圈层提示或生成指令。内部主键稳定保留，不当展示昵称。

允许短问题、顺口补充、犹豫、纠正、认真长评、善意吐槽和未解决的结尾。不要全员热情、条理完整，不全员无标点，也不把“蹲/救命/家人们”循环插入当自然感。活动通知仍需准确清楚，不硬塞梗。

## 讨论串与事实

生成时提供作者、父评论、活动关联和已确认约束。回复必须回应上下文，允许不参加、不同意和继续追问，不能全串都是赞美。一级评论与一层回复保持原有 ID、作者及关系，不把无关回复贴到另一帖。

活动有明确主题、时间地点或参与方式，普通吐槽不能改个分类就冒充活动。状态、报名数、时间地点从业务字段计算，不能让模型自由写“正在报名”。不用未提供的地址、官方认证、证书、学分或金额充实内容。

## 流水线与预算

1. 入口先通过 ensureContentCache 恢复并核对 `.data/content-cache`，再准备人物与结构计划，ID、标签、关系、时序由可校验输入约束。
2. 使用全局 Pi ModelRuntime SDK 调 DS，所有请求先经预算预留，模型不获得文件和网络工具。
3. 按逐帖和完整评论 ID 校验结果，拦截空白、截断、错误页文本、无效用途和缺评论。
4. 在 `.data/content-cache` 保存有效逐帖检查点，失败记录保留，递减拆批恢复，不重复支付已通过内容。
5. 抽审人物连续性、对话承接、口吻分布和素材主题，再扩量或导入。
6. refresh/generate 成功且通过快照校验后自动 pack，中间资料以 generated-content.tar.gz 提交，最终快照以 snapshots.tar.gz 提交并自动恢复到 .data/snapshots-cache。生成/校验或 pack 发布前失败保留旧包，本地内容保留，不能为解包或补缓存自动重新付费。归档已提交但本地状态失败时，按 DATASET 的提交边界报告，不声称已回滚。
7. 导入通过 append receipt 与事务提交后的 hook，不让 Web 页面直接调用生成服务。

累计上限 10 美元，旧账不清零。每次请求完整预留 0.02 美元，未知 usage 保留预留，不伪造实际成本。并发与重试有限，异常计价或超过额度停止新请求，不能因更换目录重新获得预算。

图片获取单独执行 `pnpm data:assets`，成功后自动写入 assets.tar.gz，恢复与打包规则见 DATASET 的图片归档章节。正文生成器不联网获取图片。

缓存文件发布统一走 writeContentCacheFile，不在网络请求期间持缓存锁。归档清单、提交边界、本地增量与包变化冲突的统一规则见[中间资料说明](DATASET.md#中间资料归档与恢复)，不在各生成器另设静默覆盖规则。

## 时间与行为

活动发布早于相关参与，评论晚于帖子，回复晚于父评论，回顾发生在对应活动之后。统一平移旧结构时保留相对顺序，正文中的具体日期需要重新核对。

关系与行为可以由确定性程序产生，不为每次状态变化调用模型。关注与好友分开，当前状态与历史行为分开，阅读心跳不当成独立曝光。不得将这些结构核验解释成真实用户推荐效果。

## 验收

小样应覆盖通知、约伴、提问、回顾、长文与完整讨论，不仅挑最好看的几篇。批次完成、逐帖通过、全量覆盖、语义抽审、导入成功和页面验收是不同状态，分别记录。当前执行进度见[内部数据说明](DATASET.md)，调用与预算实现见[Agent 工具](AGENT_TOOLS.md)。
