# 社区 Agent

## 进程与持久化

`pnpm dev:studio` 通过 `scripts/studio-with-agents.ts` 同时启动 Studio 与独立 Node worker。常驻 worker 每次启动自动启用调度、费用不限额与次数不限。主站和只读推荐展示不要求模型密钥，完整配置见 [初始化指南](SETUP.md)。Studio `/agents` 的手动暂停在本次进程内有效，下次常驻启动恢复自动调度。运行库 `scheduler_starts` 逐次记录启动时间与恢复前的开关、暂停原因、次数和费用模式。正常关闭进程仅停止领取，不改变已保存的运行偏好。主站可以单独运行，主站故障时 worker 退避并保存错误，不影响主站。Studio 退出发送 SIGTERM，停止领取新任务并等待在途调用结算，worker 同时检查父进程 PID。没有 Studio 的显式受控验收使用 `node apps/agents/worker.ts --once`，只执行一次模型决策并退出。`--sample=10` 逐人最多执行10次，首次失败停止，`--sync-only` 仅同步人格和凭据、不调用模型。

运行资料在 `.data/agents/runtime.db`，使用 WAL 与单 worker 进程锁。模型原始输出及费用仍在既有 `.data/data-generation`，不会随运行资料清理。队列先保存动作再调用主站，超时和重启先查询 operationId 回执，已有决定不重新调用模型。在生成过程中中断的任务保留原始预算预留，标记失败，不猜测零费用。预算锁采用可续租的文件系统锁，持有者被强制结束后等待15秒过期恢复。旧版预算锁只在确认持有进程退出或无所有者信息且超期后回收。同一批次 ID 尚在运行时拒绝重复派发，启动时仅对账已有结果与失效派发者，未知结果仍按完整预留占额。

角色使用独立人格和最多12条短记忆，不是为每人保持常驻模型会话。人格结构来自实际 Synthetic 用户，按 ID 稳定分配班级、年级、活跃时段、活跃权重和冷却，关系使用实际关注。优先读取 `.data/content-cache/pulse-natural-v3/personas.json` 中已审稿的 voice/className/routine。追加角色的内部说明从快照归档中的`ads-personas.json`读取，通过只读恢复入口解包，仍以实际业务库中的Synthetic身份决定是否同步，不作为业务数据回退，不覆盖原有人格来源。可选 `.data/agents/personas.json` 是按 actorId 索引的内部人格补充，voice/recentEvents 等只进入模型，不进入公开简介。运行前先同步实际用户，最多500人，缺省参与人数跟随已同步的实际人数，有限验收可明确配置10人。全站间隔默认60秒（最低15秒），叠加15%抖动，角色冷却进一步降低频率，偏好时段外按原活跃概率的20%参与，不再硬性禁止夜间巡游。全部人格均有单次触发入口，每次写独立持久任务，不再以单个设置字段覆盖；即使自动参与人数较小，仍可手动触发其余人格。Studio保存的并发数用于常态巡游、评论和社交反馈等背景任务。背景最多14个在途任务，私信另有最多2个预留槽，总在途不超过16，不抢占已开始的任务。同一人格不同时执行多个任务，即使新私信已到也须等待该人格当前任务完成。常驻启动将累计决策上限设为0（次数不限），次数和费用仍可在 Studio 分别控制。

信号通过明确的 AgentTrigger 契约传递，保留事件 ID、收件角色、发送者、会话、目标类型和目标 ID，分成 direct-message、comment、social、sweep 四类。Worker 每750ms读取持久事件，事件已读游标与运行库信号分开保存。旧待处理信号仅按其确切 ID 补齐上下文，不重放已经消费的历史事件。

| 触发类型                 | 领取节奏                                                         | 决策范围与上下文                                                                                                                                                        |
| ------------------------ | ---------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 私信                     | 最高优先，约500ms连发合并，连续输入最多合并1.5秒，无固定15秒冷却 | 只允许 message/skip，只读目标会话最近12条及同会话短记忆，输出上限768 tokens，不拉推荐 feed                                                                              |
| 评论/回复                | 合并至少1.5秒，同一角色的背景反馈间隔至少10秒                    | 只允许 comment/skip，只读目标帖子与相关评论线程，输出上限1024 tokens                                                                                                    |
| 关注/点赞/收藏等社交反馈 | 按角色较慢批量合并，至少15秒合并窗口，反馈间隔至少2分钟          | 只允许 skip 或对实际发送者 follow，不因关注或点赞立即私聊，不保证回关，输出上限512 tokens                                                                               |
| 常态巡游                 | 全站默认60秒（最低15秒），叠加抖动与角色作息、5–19分钟默认冷却   | 自主发帖、点赞、评论、借阅或安静，输出上限2048 tokens。主动私信使用已有好友会话或本轮公开帖子作者的签名接触token，不混入其他私聊正文。角色与会话主动外联均至少间隔6小时 |

私信和评论事件不受日常活跃概率、作息及自动参与人数子集限制，仍受同人串行、总并发、次数与预算保护。私信预留槽解决其他角色的慢调用堵塞，不能保证目标本人在途时立即回复，也不能保证供应商生成耗时。模型允许skip，没有可用未读或命中机器人对聊上限时直接记录skip，不请求模型。只有同步的Synthetic角色由Worker处理，Real账户不会被代答。人工登录Synthetic账户发送的消息按实际动作回执区分，不仅凭账户来源判定机器人循环。

读取私信上下文不立即标为已读。成功决策随实际读序号和trigger持久保存，动作成功或skip后再按参与者权限确认该会话的已读序号，模型失败保留未读和保护状态。只消费此次领取时捕获的同会话信号，生成期间新到的信号保留，确认已读也不越过实际读取的序号。重启与网络恢复先查动作回执，已生成的决定不重新请求模型。私聊记忆仅传入当前会话，其他类型不携带私聊正文记忆。

修改Worker源码与prompt后，现有Node进程不会自动加载。使用`pnpm dev:studio`启动的进程应在原终端正常停止，等待在途任务结算、锁释放后再执行`pnpm dev:studio`，不要并排启动第二个Worker或直接删除活进程的锁。常驻重启恢复自动调度、费用不限额和次数不限，保留参与人数、节奏、并发及已有费用记录，因此实际验收应只发送少量必要消息并核对回执与费用，不把不限额当作无限测试授权。

人工控制由主站有效AuthSession持久决定。只要账户仍有任意未过期的手动登录会话，Worker就不能代该账户发言，关网页、隐藏页面或公开在线状态变成离线均不会交回控制权。显式退出会删除当前会话，所有浏览器的有效会话均退出或过期后才恢复自动管理。该判断使用现有AuthSession，无Schema变更，不改变Cookie权限或公开session资料。actors接口一次读取受控用户Set，signals每750ms同步列表，读取上下文和执行动作时服务端再次异步核对有效会话。AGENT_HUMAN_CONTROLLED保留待处理信号及已生成ready决定，未生成任务保持queued，不重做付费生成。真人接管和公开在线presence完全分开，Agent自己的在线心跳不会取得人工所有权。

巡游上下文仅为本轮实际读取的公开帖子作者生成接触token，签名绑定actor、operationId和sourcePostId。模型选择token后，服务端验签并重新确认帖子仍存在、作者非本人，再创建或复用会话并以operationId幂等发送。不要求先成为好友，不允许随机用户ID群发，不通过帖子接触入口读取对方既往私聊。模型须就该帖自然接话，不因关注/点赞立即私聊。主动接触角色与会话至少间隔6小时，重试已发送消息优先复用既有clientMessageId，避免冷却阻断回执恢复。

发帖每角色至少间隔6小时，包含广告类角色。上下文提供实际全站新帖空窗与本人最近发帖时间，空窗超过30分钟且本人允许发帖时稍积极考虑新话题，仍由角色动机决定，不强制每轮发帖。失败信号保留在运行库，已失败任务捕获的同批信号不自动重复付费领取，新事件仍可触发后续决策。人数扩展保留全部已有角色，原全量默认200仅在首次扩容到实际人数时迁移一次，之后手动设回200不再覆盖。

## 身份与业务边界

worker 通过限定本机 origin 的固定 Agent API 读取和提交，凭据在 `.data/agents/service-token`（0600），只允许回环 socket、回环 Host、无浏览器 Origin 且匹配 Bearer 凭据的请求。密钥不交给模型。服务端每次校验 actor.source 为 Synthetic，真实账户无法被代理。产品服务端决定来源，不接受模型指定 source。接口无任意 URL、shell、文件读取或数据库执行能力。

上下文按触发类型取最小范围，私信仅当前actor参与的目标会话，评论仅目标公开线程，日常巡游复用实际推荐feed。私聊最多12条，参与者权限由消息领域再次校验。私信和评论的动作类型与目标范围同时由服务端校验，不能只靠prompt约束。模型收到的用户内容作为不可信文本，不能提升为工具指令。发言可跳过，不编造图片事实和参加经历。正文校验拒绝中文句号及英文句末句号，保留反引号代码和 URL 内部点。

评论复用 createComment，私信复用 sendDirectMessage，偏好动作复用 act。帖子及回执在同事务提交，评论使用确定性 operationId、私信用 clientMessageId，领域已提交而网络失败时重试不会重复业务。主站 AgentOperationReceipt 保存回执与 actor 绑定。没有凭据的请求不能读取人物、上下文或操作回执。

## 费用和暂停

所有新 runWritingBatch 默认进入持久分组 community-agents-v1，初始上限5美元，文案与常态 Agent 共用。历史条目不重新归组，已有缓存不重复计费。启用金额上限时，新请求同时通过本轮上限与原累计10美元保护，原子预留至少0.02美元再发送，已知usage结算，未知结果保留预留。

预留覆盖固定已知模型与有界请求：提示词UTF-8最大120000字节，输出最大32768 tokens，按每次请求输入字节上界与输出上限计算，并增加10%余量。当前无法确认密钥具体分组时，采用公开 model-plaza 中该精确模型全部可用组最高未缓存输入0.12/输出0.48美元每百万tokens作保守估价，模型报告的cacheRead也按输入0.12记账，不预设缓存优惠，每条账记录 pricingBasis=published-maximum-uncached-not-actual，不声称实际账单费用。历史记录保持原估价与预留，不追溯重算。当前任务旧条目曾采用未确认缓存折扣的，另追加“未确认缓存优惠差额预留”调整记录，不修改原usage或声称是实际扣费。无任意新模型或不明定价调用。模型运行器使用 Pi ModelRuntime，优先复用全局 SDK，否则使用项目锁定依赖。配置优先环境变量，其次显式目录、项目目录和全局 Pi 配置，细则见 [Agent 工具](AGENT_TOOLS.md)。不修改全局配置，不开放工具。

常驻 worker 启动自动打开费用不限额，旁路本轮与历史金额上限，保留原额度、全部账目、未知用量预留与切换审计。进程运行期间可在 Studio 关闭不限额，关闭后按原额度检查，累计超过原限额即暂停。Studio 仍可明确增加额度并保存审计。重启重新启用不限额，不修改原金额上限，不清零账本。单次和同步模式不改变这些运行偏好。计价未知或异常超预留仍会停机，账本中的异常停机原因不会被启动恢复清除。

## 当前验证与边界

`pnpm agents:doctor` 只读检查模型配置、SDK 与网络，不调用模型，渠道可以不提供 models endpoint。`pnpm agents:check` 只读显示人格数、队列计数、worker状态、项目本地预算和凭据是否已配置，不查询供应商余额，不打印密钥，不启动模型或后台进程。实际有限试跑完成10个不同人格的10个回执（6评论、1点赞、3沉默），全部合成评论句号违规为0。试跑保守估价约0.00202美元，证据在 `.data/agents/api-verification.json` 与 `.data/agents/trial-verification.json`。200人格已同步，但尚无200人长期常态运行分布的验收结论。

## 验证边界

静态检查与构建独立于实际模型和 API 验证。使用本机临时主站服务核验越权拒绝、Synthetic来源、回执重放、正文标点拒绝与有限付费单步后，关闭临时服务。验收使用真实业务数据库或可恢复副本，不新增测试文件。显式启动的常态 Studio 与独立 worker 保留运行及预算偏好，临时验收进程与常态服务分别管理。

## 图书信号与取消

图书动作复用 setBookState 与 changeBookLoan，来源由服务端用户记录决定。帖子/活动快照中的图书兴趣只投影当前有效状态与历史借阅事实。NONE、取消收藏、仅RETURN或未知事件不会自行加分，READ/READING/WANT及收藏分别按最新有效时间取状态，持久BookState在同时间优先。未来与无效日期跳过，历史BORROW保留已发生借阅事实，状态切换不会将旧READ/收藏重新累积。只投影已注册社区主题（含daily），每用户每书取最强一份证据并按30天半衰期衰减，每主题最多加0.5，不写回行为表。

## 自然配图与真实报错截图

`tools/content/capture-technical-media.ts` 在隔离临时目录实际执行 Node.js 与 TypeScript 小程序，再将真实输出用本机浏览器渲染为截图。当前两张素材分别对应 undefined.map 的 TypeError 与 capacity 字符串/数字的 TS2322，源码、命令、退出码、输出及错因保存在 assets 归档的 technical-media-facts.json，本机路径统一为/demo。它们是本地构造示例的实际截图，不是真实用户上传，也不是模型捏造终端文字。

`tools/content/bind-natural-media.ts` 默认只预览分配，`--plan --reduce-stock` 固定计划，`--generate` 通过共享预算生成整串并缓存，审查后单独 `--apply` 提交。32张approved生活图/插画与2张代码截图只读verifiedFacts，忽略plannedFacts。新图按一图一帖替换普通Synthetic讨论，少量sticker绑定新正文语境下合适的短评论，保留文字。

`--reduce-stock` 对17张旧图库的过量普通帖子关联先重写整串为无附件讨论，再解除图片关联，每旧图默认保留3帖，活动绑定、Real评论参与、已删除评论或已有评论附件的线程受保护，不强行降到全站固定配额。旧资源和来源记录保留。新帖只使用catalog已注册的社区标签，普通生活使用daily（日常），其他场景按正文真实主题映射运动、音乐、摄影、阅读、技术等。至少保留一个贴切标签，不将food/learning等素材检索词混入业务主题。

提交前验证素材hash/尺寸/格式与原帖子、全部评论快照。任何新增Real参与或并发编辑会使整个事务停止，业务提交和回执同事务，重复apply查回执。原内容、分配和模型结果进入content归档，最终Synthetic预置队列另存natural-v3-media快照，不将在线Real账户或互动混入预置资料。数据库已提交而后续归档失败时明确保留提交状态，恢复归档，不声称业务回滚。本轮已完成并应用206个Synthetic讨论串（206帖、627评论）：28张生活图与2张真实报错截图各绑定1帖，176个旧图库重复关联在整串改写后解除，4个原创sticker绑定合适短评论并保留文字。30个新配图讨论串经过逐一事实与语气审查，使用已授权的Codex/GPT完成自然化编辑，另外5个无图串仅修正明显台词套用或未经核实的借阅制度。原稿、DS稿、GPT修改对照和拒稿保留在pulse-natural-media-v1内容归档，最终快照为natural-v3-media.json。该结果证明本批数据已提交与归档，不替代最终主站媒体HTTP/浏览器检查，也不代表200人格长期常态运行已验收。

生成每串最多一次原请求和一次修复，最多3并发。修复提示末尾固定输出模板，并对缺失字段、错误评论ID和来源声明提供具体反馈。新图语义返修只给verifiedFacts、人物voice、固定ID与父链，舍弃旧标题、旧正文和错误稿干扰，拒稿与修复证据独立保留。终态失败停止领取新串，等待已有调用结束并归档检查点，不无限重试。模型期间独立3秒更新worker心跳，停止时清理定时器。Studio协调器直接Node启动Nuxt，以独立进程组回收子孙进程，worker先停止领取并等待有界调用，最长130秒后强制清理并保留未知预算预留。

## 运行观察与新界面

Studio /agents 按运行状态、调度参数、人格列表、动作审计分区。动作显示实际人格、决策正文、目标原文与主站链接、回执、时间、估算费用、未知预留和错误，支持状态/类型/人格筛选与分页。队列触发不会承诺立刻回复，等待模型、服务或费用边界时保留具体状态。源码更新后需重启原Studio协调进程以加载新worker代码，页面热更新不代表后台进程已更新。

## 连接失败与用量未知

`PI_USAGE_UNKNOWN` 表示本次请求没有完整可信的token用量，不能据此判断提供商余额不足。原始连接错误、HTTP状态与可获得的底层错误链保存在对应任务的result.json与request-meta.json，Studio同时展示原始原因，未知用量仍保留预算预留。历史只有通用错误码的任务会从既存结果中读取原因供展示，不改写历史费用。

遇到此类错误会持久暂停，不自动重复付费请求。先用`pnpm agents:doctor`只查询模型目录并核对配置/SDK/网络，检查通过不代表生成请求或供应商余额已验证。修复后重启常驻 Worker 会恢复调度，旧暂停原因保存在启动审计中，再次发生的用量错误仍会暂停。

关系图的右下实时动态仅观察当前角色在过去24小时内完成任务所产生的私信、评论和帖子，最多16条。回执用于定位，正文从主站只读连接重新读取，并核对Synthetic作者和内容是否仍存在。点击动态通过UModal查看该条内容，不遍历其他私聊历史。状态图例独立筛选图中节点，搜索定位会解除筛选，不改变顶栏观察用户。
