# Agent 协作实施

## 协作入口

主 Agent 先读 AGENTS、当前任务、相关源码、Git 状态和契约，确定范围与验收证据。优先使用 Codex 内置多 Agent，只有明确采用 Seedmux 时才使用对应 pane 流程，不虚构委派或回执。

并行之前先发布实体关系、DTO、错误码与接口。默认共用工作区，同一文件只给一个负责人。根配置、锁文件、schema 与共享契约由指定主维护者集中集成，允许明确移交，不能让多个 Agent 同时修改。

## 文件边界

| 角色         | 主要范围                                                   |
| ------------ | ---------------------------------------------------------- |
| 主 Agent     | 根工程、共享契约、schema、阶段目标、集成与最终验收         |
| 产品 UI      | apps/web/app、对应 i18n、public 与实际 API 联调            |
| 业务 Agent   | apps/web/server、packages/domain、受授权的 schema/契约修改 |
| Studio Agent | apps/studio、packages/recommendation、可选追踪             |
| 内容维护     | tools/content、tools/agents、DS 审样、结构校验与费用记录   |

角色是文件责任分工，不伪造人的贡献。任务写清目标、输入、输出、允许目录、禁止文件、依赖契约和验收方式。子 Agent 自述通过仍需主 Agent 独立核对。

## 推进

1. 保留可恢复数据与既有源码成果，建立最小业务闭环。
2. 冻结主要接口与数据契约后并行实现，变更共享契约先通知相关负责人。
3. 内容先人物与完整讨论串小样，再根据审样结果扩量，不能只靠机械增加“蹲/救命”制造口语感。
4. 回收实际产物、检查结果和遗留问题。失败也报告，不把文件存在当作交付。
5. 运行 format、lint、typecheck、build，再分别检查实际 API、浏览器、图片、modal、分页、身份隔离和生成内容。
6. 实际截图和验收记录区分版本，不改写旧记录冒充新验收。临时服务完成即关闭。

不新增测试文件，不清理其他 Agent 未提交改动，不擅自 stash、reset、clean、提交、推送或部署。独立工具和 Studio 不应混入 Web 构建。

## DS 任务

DS 经全局 Pi ModelRuntime SDK 处理有界写作上下文，不能把内置 Agent 的模型名当第三方调用入口。所有批次通过预算函数预留，累计上限 10 美元，未知用量完整预留。原始输出、逐帖检查点、回执和 usage 保留。

自然度判断与工程正确性分开。结构化 JSON 成功不代表回复接得上话，模型说“我检查过”不代表权限、事务或算法经过验证。新内容通过 append 导入回执和提交后 hook 集成，不把生产者挂到 Web 公共路由。
