# UI 与交互规范

## 产品定位与视觉

在场是校园活动与内容社区。参考内容产品的信息层次、图片浏览和讨论阅读，不复刻品牌或搬运真实用户内容。公共产品文案只描述实际业务，内部数据来源、生成流程和费用信息留在独立工具与内部记录。

以灰白、明暗中性色为主，蓝色只做少量交互点缀。避免深色或大面积 primary 实心块，不能让默认组件配色压过内容。侧栏发布按钮作为明确操作，使用主题蓝底与白字，hover 小幅加深。浅色、深色与跟随系统三模式均可用，主题入口使用太阳/月亮/显示器图标与可访问名称，不再使用文字下拉框。

产品品牌使用无背景的单线字母 P SVG，“在场”置于图标下方，不附品牌 tagline。侧栏品牌与导航之间保留充足间距，底部主题切换拉满可用宽度、等分对齐。首启短描边不能延迟内容，不随每次导航重复播放。favicon、桌面、移动端和后台使用同一图形语言。

## 页面结构

- 桌面三栏，各路由在相同断点使用同一左列宽度，不因右栏有无改变导航宽度：左侧安静导航，中间内容，右侧当前用户摘要、近期日程、推荐活动和兴趣。右栏只展示实际数据，不添加装饰性统计。
- 发现页顶部为推荐/关注与搜索、主题筛选。不要首页 hero 大卡片，也不要“为你发现”标题与说明两行占位。
- 活动页直接呈现与发现页同风格的搜索及筛选，不显示顶部装饰英文、大标题或小副标题。
- 一级入口保持发现、活动、我的，发布为明确操作。实验、生成、身份模拟和数据恢复不放入产品导航。
- PC 个人主页内容为三列。窄屏按真实可读宽度降列，不能只把三列缩小。
- 校区统一使用 `packages/contracts/catalog.ts` 的铜盘校区、鼓山校区、旗山校区，选择器、API 校验、导入和已有数据必须一致。
- 活动详情和报名属于 Activity，帖子可以关联活动，不能建立第二套容量与报名记录。

## 卡片与媒体

帖子维护内容包以 65% 标题大字报、35% 场景图为分配目标，允许范围为 60–70% 大字报。当前 1000 帖已通过全部公开 PostView 投影核验，实际为 650/350，记录见 `.data/final-poster-ratio-review.json`。Real 内容和未知/上传图片保持原样，不为配额覆盖用户图片。推荐分页保持原有排序，不按每页强制凑比例。

每张内容卡片都必须有封面。采用来源明确的主题场景图和根据实际标题/标签排版的大字报两种形式。帖子没有自身有效媒体或图片加载失败时显示对应标题封面，不使用关联活动封面作为后备帖图，不显示纯文字卡片或空白媒体框。活动自己的详情封面仍独立保留。正常分支比例以 `PostView.media` 统计，加载失败产生的额外回退另记。

图片和大字报不能与内容主题冲突，不能把场景素材写成参与者现场实拍。媒体提前保留比例，避免瀑布流跳动。卡片突出封面、标题、必要摘要、作者/主办方与互动，活动关联信息包括真实时间、地点和状态。帖子卡片不加 border，hover 不出现描边或阴影，只对整体应用约 brightness(.95)，鼠标为 pointer。帖子与活动统一使用轻灰卡片表面，与页面背景保持细微区分，浅深色均不加 border、hover 描边、阴影或文字下划线，整体轻微变暗并显示 pointer。

卡片不展示算法总分、数值权重、耗时和完整贡献表。按需推荐理由只使用真实匹配标签与社交证据，不能写死“因为你喜欢摄影”。

## 详情、路由与滚动

帖子、查看活动、新建活动使用路由 query 驱动的 modal：`?post=:id`、`?activity=:id`、`?activity=new`。打开保留底层列表，关闭/后退恢复原来的浏览位置。canonical `/posts/:id` 通过服务端 302 到 `/?post=:id`，不单独渲染详情页。`/activities/:id` 与 `/activities/new` 分别通过服务端 302 到 `/activities?activity=:id`、`/activities?activity=new`。保留筛选等其他 query 与 URL fragment，覆盖目标 ID，移除其他内容弹层的冲突字段，保留认证 query，使直接打开、复制链接和新标签访问均进入对应详情弹层。直接深链关闭后清除当前详情 query 与详情 fragment，保留对应列表背景，不后退到外部站点。

详情 modal 外层不加 border、ring 或组件默认 divide-y 分隔线，避免图片边缘出现白边或黑边。多图帖子使用真实媒体数组，可通过触摸滑动、左右按钮、键盘和页码切换，单图不显示多余控件，无图或失败沿用实际标题封面。PC 帖子弹层左侧图片铺满自己的媒体区域，右侧正文/讨论独立滚动，隐藏滚动条但保留键盘与滚轮可达性。检查既有 max-height 是否限制图片填充，不能只改 object-fit。活动弹层采用同样清楚的图片/正文层次。活动与帖子详情的大字报统一由 MediaGallery 排版，标签在顶部、标题居中、落款在底部，字号与内边距跟随媒体区宽度，不按页面类型分别覆盖。活动“现场的讨论”按容器宽度使用两列、宽容器三列，小屏窄容器才单列。手机使用连续单列滚动，不保留两套互相争抢的内层滚动。

登录与注册使用 `?auth=login` / `?auth=register` 的路由 modal，保留下层列表及已打开的帖子或活动，关闭与浏览器返回恢复原位置和触发焦点。直接 `/login`、`/register` 及旧注册 query 转到对应 modal。登录成功留在原内容上下文，从“我的”或发布触发时继续到相应目标。

modal 使用可靠组件处理焦点、Esc、遮罩、滚动锁定和关闭动画。上传/提交中、浏览器后退、切换 query 和组件卸载都要清理 busy 与异步状态，避免再次打开后无法关闭。未保存内容离开提示与实际路由形态一致。

## 动效

首屏与新追加内容短暂淡入，已浏览内容不重新播放。筛选、状态变化、详情开关保持连续，追加内容不重排已有内容。卡片与 modal 的动画可以中断，不能依赖定时器才能恢复点击。

颜色模式切换使用浏览器 `document.startViewTransition` 的短淡化过渡，页面路由切换使用轻量透明度与短距离位移过渡，不支持时直接切换。

减少动态效果偏好下取消描边、位移、缩放和自动播放，保留即时反馈。动效完成、关闭动画和图片失败都要验证，不用 Build 代替实际观察。

## 移动端与表单

手机采用顶部品牌/搜索与底部发现、活动、发布、我的。常规宽度双列轻卡片，极窄或大字体场景单列。右栏功能进入个人页或内容流，不整段搬到首页上方。

输入、选择、按钮与弹层优先使用 Nuxt UI，后台使用 TDesign，不用全局原生控件样式覆盖组件库。重要触摸目标约 44px，检查安全区、软键盘、长标题、大字体和焦点状态。

游客不显示右上用户信息卡片。详情加载失败使用居中的图标、提示与重试按钮，重试期间保留错误布局并禁用重复触发。错误留在相关表单或内容区域，失败保留输入。报名明确已报名、截止、开始、满员和取消状态。一级评论与一层回复，头像在左，昵称、正文、时间与回复入口依次排列，回复缩进并标明作者身份，不使用逐条横线、回复背景块或伪造的点赞/地区。多条回复可展开或收起。评论总数下先显示头像与圆角输入入口，再显示评论列表，时间和回复入口同排，回复透明底且不加逐条分割线。

## 内容流与验收

触底加载使用服务端游标，去重、失败重试、无更多、身份切换和会话失效均有明确行为。返回恢复采用显式有界缓存，核对身份/筛选隔离、闲置过期、内容与游标的完整检查点和容量，不依赖 KeepAlive 代替内容缓存。首页在离页前记录用户滚动位置，等待瀑布流测量并应用行跨度后，以有限双帧恢复一次，再启用触底观察。首页禁用滚动锚定，不用无限 timeout 或持续强制滚动修补位置。

瀑布流按实际内容高度测量，细行跨度加统一 gap，不以粗行取整制造不一致空隙。保持自动触底追加，只降低自动请求频率，触发间隔约 1 秒，不增加“必须继续滚动一定距离”的门槛，不用手点“加载更多”，仅在真实游标耗尽时显示“已经看完了”，不把单批结束当作内容耗尽。布局测量完成后重新检查触底位置，剩余内容仍在视口附近时自动续接。P 标识只在实际请求期间显示加载动效，不用假延迟延长 loading。

DOM 顺序、视觉阅读顺序和推荐顺序一致。新内容提示不能强行抢走阅读位置。自动滚动只在 Studio 的独立内容预览启用，用户操作立即接管，到末尾停止，不产生产品阅读证据。

验证桌面三栏、PC 个人页三列、手机、浅深色、键盘、大字体、图片失败、长内容、modal 开关与浏览器后退。文档规定的目标不是验收已完成的声明，实际证据另行记录。

## Studio

Studio 使用相同 P 品牌与浅深色中性背景，页面标题为“在场 Studio”。顶栏固定在视口顶部，设置侧栏在桌面独立滚动，手机可展开。算法阶段导航直接置顶，不使用大标题、GRAPH/SCORE/TOP-K 装饰标语、隔离环境和实现说明占位。基准时间按 Asia/Taipei 格式化，编辑与回写保持同一时刻，避免 UTC 截断偏移。内容预览使用保序瀑布流，自动滚动默认 16px/s，用户操作接管。

## 封面与个人操作

标题封面统一默认 3:4，发布可选择 1:1 或 4:3。使用 Google Fonts CDN 的思源黑体（[Noto Sans SC](https://fonts.google.com/noto/specimen/Noto+Sans+SC)），不随项目存放字体源文件，按媒体实际宽高测量字号，不用标题随机改变比例，也不裁掉标题。环形、引号与白底便笺三套模板共享卡片和详情渲染，移除左上横线与左下落款，保留箭头或引号模板的短粗线。高亮只取标题中的实际连续文字。

个人页仅保留右侧兴趣 Popover 和资料编辑入口，主题及退出使用侧栏全局入口。左侧底部头像与昵称 hover 对共同容器设置透明度，不加背景或下划线。本人评论可编辑、删除，有回复的根评论删除后显示墓碑并保留回复，空评论居中。发布使用 compose query modal，保留 canonical 路由与下层页面。

## 内容操作与滚动细节

发现卡片不显示推荐理由和主题标签，主题筛选继续保留。卡片爱心可直接点赞，选中后使用红色实心，并在成功点赞时弹跳、浮出爱心。帖子详情的点赞、收藏、评论按图标与真实数量右对齐，保留可访问名称，点赞红心、收藏星星，收藏成功后使用星星动效。减少动态偏好下关闭弹跳与浮出动画。

主站滚动保留浏览器原生滚动与位置恢复，隐藏滚动条并取消宽度占位，弹层开关不改变内容区域宽度。搜索框使用细边框，不叠加聚焦 ring 或 outline。桌面详情媒体区占 42%，正文占 58%，手机继续单列。白底便笺模板使用Google Fonts CDN 站酷快乐体（ZCOOL KuaiLe）居中文字和粗糙笔刷边缘的浅蓝高亮，不添加装饰落款。

Studio 顶栏内容流入口和账户入口使用相同常规字重，重新计算使用蓝底白字与白图标。桌面实验设置侧栏展开和收起使用宽度与透明度过渡，隐藏控件不能获得键盘焦点，减少动态偏好下取消过渡。

桌面右栏高度固定为视口高度，内容独立滚动，隐藏滚动条，面板保留自身高度。右栏滚动到边界时不将滚轮传给主内容流，键盘可聚焦滚动区域，矮屏下可以访问最底部兴趣面板。

Studio 的观察用户与主站账户选择共用搜索与分页界面。打开时不列出全部用户，输入后以 250ms 防抖查询，或主动选择查看全部。每页默认 100 人，可选择 20、50、100、200，切换查询或页容量回到第一页，过期请求取消且不能覆盖新结果。主站账户在数据库侧搜索和分页，观察用户在 Studio 主站只读数据中筛选。弹层宽度为 440px 上限，列表单独滚动，没有选中账户时不占用底部链接区域。

内容流明确区分可继续、请求中、请求失败、浏览记录过期与全部看完。读取下一页成功后续期浏览会话，长时间闲置、服务重启或会话回收仍可能需要刷新，刷新会重新读取与排序已有内容。底部保留继续浏览状态与自动续接检查，窗口重新获得焦点时重新检查触底位置，到底可主动刷新，刷新重置到顶部。

Studio 的 Top-K 阶段使用视口内的树图工作区，步骤标题与候选数同排，移除 MIN HEAP 装饰标题，堆容量显示在树图右上角。树图画布覆盖标题、状态与当前候选所在区域，标题作为透明叠层，不截断拖动后的节点与连线，支持指针拖动、方向键平移和位置复位。文本记录默认作为浮窗放在左侧当前候选下方，拖动范围覆盖阶段导航下方的整个内容区，可停靠右侧或恢复浮动，不设置额外的查看入口，记录可独立滚动并定位回放步骤。回放控件和进度条贴工作区底部，进度轨道左右铺满。侧栏收起时表单保持展开宽度并淡出裁切，不压缩文字，推荐对象下拉使用紧凑弹出宽度。

Studio 参数变化后自动重新计算，连续输入以 150ms 防抖合并，旧请求取消并校验参数签名。计算期间保留上一份结果与对应的用户、目标、时刻、K 上下文，不因参数变动卸载图形工作区，非法或暂时为空的输入不发请求，显示参数提示。空堆到非空堆的底部数组栏使用高度过渡，减少动态偏好下取消过渡。数组可横向滚动但隐藏滚动条，进度圆点加大并完整保留在控件高度内。

发现页使用 q、tag、tab 路由参数保存搜索、主题和推荐/关注切换，活动页使用 q、tag、campus 保存搜索、主题和校区筛选，默认值省略。搜索防抖后写入浏览历史，离散筛选立即写入，刷新、前进后退和打开/关闭详情均保留对应筛选。首页缓存只在身份与路由筛选一致时复用，不用旧缓存覆盖链接中的筛选。
