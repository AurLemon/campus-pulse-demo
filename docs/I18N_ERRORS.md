# 国际化与错误处理

## 语言与目录

- 界面、导航、按钮、表单、占位符、空状态、无障碍标签、页面标题和错误提示全部通过 i18n 管理，不在组件或 API 中散落用户可见字符串。
- 使用 Nuxt I18n，当前只启用 zh-CN（简体中文），不展示尚未提供的语言选项。已启用语言必须覆盖同一组 key，新增 / 修改 / 删除同步所有语言，不能用默认语言回退掩盖漏译。
- 翻译放在 `apps/web/i18n/locales/<locale>/`，按业务拆分文件，每个文件只导出对应命名空间，避免同层覆盖。
- 建议模块为 `common`、`app`、`feed`、`posts`、`comments`、`activities`、`social`、`profile`、`recommendation`、`validation`、`errors`，实现模块时才添加实际用到的 key，不预填虚构业务状态。
- 日期、时间、数字与复数使用对应 locale 的格式化能力，不能用中文字符串拼接英文。业务时刻统一存储，产品展示时区与 Studio 实验时刻分别明确。
- 帖子、评论、用户昵称等内容保留原文，界面语言切换不自动改写用户内容。分类标签的稳定 ID 与显示文本分离。
- UI 组件库的语言包与应用 locale 同步，包括日期控件、分页和默认提示，不能只翻译应用自写文案。

## 业务错误契约

服务端错误以稳定的大写下划线错误码区分，例如 `VALIDATION_FAILED`、`ACTIVITY_FULL`、`REGISTRATION_CLOSED`、`FORBIDDEN`、`NOT_FOUND`、`INTERNAL_ERROR`。错误码是程序契约，不随界面语言变化。

预期错误应保留正确 HTTP 状态：参数问题 400 / 422，未登录 401，无权限 403，不存在 404，状态冲突 409，限流 429，未知服务错误 500。不能所有失败都返回 200 或一律改成 500。

响应只包含可公开的 code、允许展示的插值参数、字段错误与可追踪的 requestId。框架必需的 message 使用安全英文摘要，客户端按 code 映射本地化文案，不直接显示原始异常 message。未知 code 回退到统一可理解提示，映射表使用白名单，不能把任意服务端字符串当成翻译路径或 HTML。

日志保存诊断所需的技术原因、堆栈、状态与 requestId，过滤密钥、会话凭据和不必要的个人数据。客户端不暴露 SQL、Prisma 堆栈、本机路径或原始请求体。

## 前端反馈

- 字段错误显示在对应输入旁，提交时聚焦首个无效字段。客户端与服务端规则保持一致，但不能仅依赖客户端校验。
- 无法归属字段的失败在当前表单 / 内容区域持续展示，保留输入和草稿，不因失败关闭弹窗或清空内容。
- 不用短暂 Toast 承载表单校验或提交错误。成功提示按实际交互决定，错误不能只靠颜色表达。
- 网络中断、超时、无权限、已截止、满员、重复操作与未知错误分别给出可理解反馈，说明能否重试或下一步怎么办。
- 乐观更新失败需恢复状态，重复提交需受控。报名等写操作超时后结果可能未知，先查询状态或按幂等机制确认，不能盲目重试造成重复写入。
- 全局错误页覆盖 404 和未知异常，提供返回入口与必要的追踪信息，遵循当前界面语言。
- 取消请求不提示为失败，组件卸载后的旧请求不能覆盖新页面状态。加载、空结果与失败分别建模。

## 核验

核对所有已启用语言的 key 集合，检查插值、复数和组件库语言。验证错误状态、字段映射、未知错误兜底、草稿保留与重复操作，不额外编写测试文件，不使用假接口返回冒充核验结果。

## 当前接入

- `apps/web/nuxt.config.ts` 注册 Web 分模块语言文件，`apps/studio/nuxt.config.ts` 注册独立实验室语言，两者均为 no_prefix、zh-CN。
- Web 语言资源在 `apps/web/i18n/locales/zh-CN`，Studio 在 `apps/studio/i18n/locales/zh-CN.json`，不要把两个应用的 key 靠偶然同名混在一起。
- `apps/web/lib/ui-locales.ts` 适配 Nuxt UI 与 TDesign，Web 的 UApp 与后台 ConfigProvider 采用中文资源。
- Web 公共错误使用 code、fields、requestId，客户端白名单映射，包含 FEED_EXPIRED、UNAUTHORIZED、FORBIDDEN、ACTIVITY_FULL 等状态，不直接展示原始异常。
- 取消、身份变更和组件卸载的过期请求应被忽略，不作为网络失败提示。Studio 参数请求另有 AbortController、请求序列和参数签名保护。

界面资源迁移、key 完整性、首错焦点、错误留存和真实请求状态需要分别检查，不把规范条目写成所有页面都已验收的结论。
